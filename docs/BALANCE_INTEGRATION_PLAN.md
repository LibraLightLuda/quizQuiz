# 균형 저울 기존 기능 통합 개선 계획

> 구현 상태: P0~P2 항목을 적용했으며, 최종 테스트와 시각 검증 결과는 작업 완료 시점의 검증 기록을 기준으로 한다.

## 1. 목표

균형 저울을 별도의 실험 기능처럼 보이지 않게 하고, 기존 스도쿠·기억력 챌린지·이야기 탐험대와 같은 수준의 시작 경험, 기록, 피드백, 접근성, 안정성을 갖춘 독립 학습 모드로 개선한다.

개선 뒤에도 다음 원칙은 유지한다.

- 한 세션 5문제, 시간 제한 없음
- 힌트를 사용해도 보상을 깎지 않음
- 탭과 드래그를 모두 지원
- 서버·계정 없이 오프라인 동작
- 속도 경쟁보다 등식의 관계를 이해하는 경험을 우선

## 2. 현재 상태와 차이

| 영역 | 기존 기능의 공통 수준 | 현재 균형 저울 | 판단 |
|---|---|---|---|
| 첫 사용 | 스도쿠는 단계별 연습, 다른 게임은 규칙 설명과 미리보기 제공 | 바로 단계 선택 후 문제 시작 | 보완 필요 |
| 입력 안전 | 일반 학습은 입력 잠금, 스도쿠는 무작위 연타 방지 | 컴포넌트 상태에서 직접 처리 | P0 |
| 피드백 | 현재 상태와 다음 행동을 어린이 문장으로 안내 | 차이값은 안내하지만 초과한 경우에도 “더 필요해요”라고 표현 가능 | P0 |
| 단계 이름 | `첫걸음·쑥쑥·척척·달인`처럼 앱 안에서 반복 사용 | `처음·차근차근` | 통일 필요 |
| 진행 표시 | 문제 수·활동 수와 별 보상을 분리 | 완료 문제를 별 개수로 표시하고 결과는 별 5개 | 혼동 가능 |
| 기록 | 최고 기록, 완료 횟수, 일일 배지 또는 도감 제공 | 완료 세션·문제 수만 저장 | 확장 필요 |
| 이어하기 | 진행 위치와 현재 상태를 저장하고 복구 | 문제·배치·힌트·이동 횟수 저장 | 기본 충족 |
| 설정 연동 | 효과음, 애니메이션 감소, 저장 실패 대응 | 효과음·애니메이션·저장 실패 대응 | 충족 |
| 접근성 | 큰 터치 영역, 키보드, 상태 문구, 색 외 표시 | 탭 대체 조작과 합계 문구 제공 | 세부 보완 |
| 문제 다양성 | 단계별 규칙 변화와 일일 문제 | 두 단계, 일반 무작위 문제 | P1~P2 |
| 테스트 | 전체 흐름·재개·연타·모바일·오프라인 검증 | 생성기·저장·첫 문제 완료만 검증 | 보완 필요 |

## 3. 제품 결정

### 화면과 용어

- 단계 표시는 `첫걸음`, `쑥쑥`으로 바꿔 스도쿠와 같은 성장 언어를 사용한다.
- 진행 중에는 별 대신 `맞춘 저울 2 / 5`를 표시한다.
- 결과 화면은 기존 결과 카드와 같이 3개의 별을 사용하되 힌트 여부와 무관하게 완주하면 별 3개를 준다.
- 이동 횟수는 평가 점수가 아니라 `이번에 움직인 추`라는 관찰 기록으로만 보여 준다.
- 홈 카드의 저울 아이콘은 코드 기반 SVG를 유지한다. 저울의 기울기와 숫자가 상태에 따라 달라져야 하므로 정적 그림보다 적합하다.

### 학습 흐름

```text
홈 → 균형 저울 → 첫 사용 규칙 연습 → 단계 선택 → 5문제 → 결과
                         ↑                       ↓
                    다시 보기              자동 저장·이어하기
```

- 최초 1회는 `추 고르기 → 접시에 놓기 → 기울기 읽기 → 추 빼기`를 실제로 해 보는 3단계 연습을 제공한다.
- 이후 단계 선택 화면에서 `규칙 다시 연습하기`로 언제든 다시 들어갈 수 있게 한다.
- 문제 중 뒤로 가기는 진행을 저장한 뒤 단계 선택으로 이동하며, `저장했어요. 나중에 이어 할 수 있어요.`를 알린다.

### 피드백과 힌트

- 부족할 때: `왼쪽 접시에 3만큼 더 놓아 보세요.`
- 초과했을 때: `왼쪽이 2만큼 무거워요. 추를 하나 빼 볼까요?`
- 균형일 때: `양쪽 합이 8로 같아요. 8 = 8이에요.`
- 1차 힌트는 차이와 해야 할 행동만 알려 준다.
- 2차 힌트는 아직 놓지 않은 정답 추를 강조하고, 잘못 놓인 추가 있으면 빼기 표시도 함께 강조한다.
- 힌트 문구는 단순 정답 공개가 아니라 `더하기`, `빼기`, `같다`의 관계를 말로 연결한다.

## 4. 단계별 구현 계획

### P0 — 기존 기능 수준의 안정성과 사용성

#### 1. 상태 전환과 중복 입력 방어

- `BalanceMode`의 직접 상태 변경을 `balanceReducer`의 명시적 상태 전환으로 분리한다.
- `playing`, `solved`, `advancing`, `result` 상태를 두어 정답 뒤 입력을 차단한다.
- 같은 추 연타, 드래그 직후 click 중복, 다음 버튼 연타가 이동 횟수나 완료 수를 두 번 기록하지 않게 한다.
- 저장은 유효한 상태 전환 뒤 한 번만 수행한다.

대상 파일:

- `src/balance/balanceReducer.ts`
- `src/balance/BalanceMode.tsx`
- `src/balance/types.ts`

완료 기준:

- 같은 추를 빠르게 3번 눌러도 배치 배열에 중복 ID가 없다.
- 한 문제의 `completedCount`는 정확히 한 번만 증가한다.
- 마지막 문제에서 결과 기록이 한 번만 저장된다.

#### 2. 피드백·힌트 정확성

- 현재 합계가 목표보다 작은지, 큰지, 같은지를 계산하는 순수 함수를 추가한다.
- 초과 상태에서는 더 놓으라는 문구를 절대 표시하지 않는다.
- 2차 힌트는 `빠진 정답 추`와 `잘못 놓은 추`를 구분한다.
- 균형 완료 문구에 실제 등식 값을 포함한다.

대상 파일:

- `src/balance/balanceGenerator.ts`
- `src/balance/BalanceMode.tsx`
- `src/balance/balance.css`

완료 기준:

- 부족·초과·균형·잘못 놓은 추가 있는 경우를 단위 테스트로 각각 검증한다.
- 문구만 읽어도 다음 행동이 `놓기`인지 `빼기`인지 구별된다.

#### 3. 규칙 연습과 용어 통일

- 3단계 `BalanceTutorial`을 추가한다.
- 첫 실행 여부를 별도 버전형 로컬 저장 키로 기록한다.
- 단계명을 `첫걸음`, `쑥쑥`으로 변경한다.
- 단계 카드에 실제 예시 `5 = □`, `7 = 3 + □ + □`를 표시한다.
- 단계 선택 화면에 `규칙 다시 연습하기`를 둔다.

대상 파일:

- `src/balance/BalanceTutorial.tsx`
- `src/balance/balanceStorage.ts`
- `src/balance/balanceGenerator.ts`
- `src/balance/BalanceMode.tsx`

완료 기준:

- 첫 방문자는 긴 설명문 없이 연습을 완료하고 첫 단계로 이동할 수 있다.
- 재방문자는 연습을 건너뛰되 원하면 다시 열 수 있다.
- 키보드만으로도 연습의 모든 단계를 완료할 수 있다.

#### 4. 진행·결과 화면 정렬

- 진행 중 별을 `맞춘 저울 n / 5`로 교체한다.
- 결과 별은 기존 모드와 동일한 3개 표현으로 변경한다.
- 결과 문구를 `무엇을 배웠는지`부터 보여 주도록 바꾼다.
- 버튼 순서를 `한 번 더`, `다른 단계`, `학습 놀이터로`로 통일한다.

완료 기준:

- 진행 수와 보상 별의 의미가 섞이지 않는다.
- 320×568 화면에서 결과 버튼과 기록 카드가 가로로 넘치지 않는다.

### P1 — 기록과 반복 플레이 품질

#### 5. 문제 생성 다양성

- 현재 `정답보다 큰 수 두 개`인 예측 가능한 오답 생성을 개선한다.
- 가능한 모든 부분집합을 검사해 정답 조합 하나만 남기면서, 작은 수·가까운 수·부분적으로 맞는 조합을 섞는다.
- 최근 10개 문제의 `목표값 + 시작값 + 정답 조합 + 방향` 서명을 저장해 반복을 줄인다.
- 좌우 방향은 세션 안에서 한쪽으로 치우치지 않게 배분한다.

완료 기준:

- 단계별 1,000개 생성 문제 모두 풀이 가능하고 정답 조합이 하나다.
- `쑥쑥`에서는 가장 큰 추가 항상 오답이라는 패턴이 성립하지 않는다.
- 한 세션에서 같은 문제 서명이 반복되지 않는다.

#### 6. 기록 모델 보강

- 단계별 완료 횟수, 최근 이동 횟수, 개인 최소 이동 횟수를 저장한다.
- 최소 이동은 경쟁 점수가 아니라 `새로운 방법을 찾았어요`라는 긍정적 피드백에만 사용한다.
- 저장 데이터 마이그레이션을 추가해 현재 v1 기록을 잃지 않는다.
- 설정의 기록 삭제 문구와 범위를 검토해 독립 게임 기록도 함께 지울 수 있게 한다.

대상 파일:

- `src/balance/types.ts`
- `src/balance/balanceStorage.ts`
- `src/services/storageService.ts`
- `src/app/App.tsx`

완료 기준:

- 기존 v1 기록을 새 버전에서 읽을 수 있다.
- 손상된 단계별 기록만 기본값으로 복구하고 게임은 계속 실행된다.
- 기록 삭제 전에 삭제 범위를 분명히 알리고 한 번 확인한다.

#### 7. 전체 세션·복구 테스트

- 두 단계 각각 5문제 완주를 자동화한다.
- 중간 저장, 새로고침, 정답 직후 재개, 마지막 문제 저장을 검증한다.
- 320px 모바일, 태블릿, PC, 가로 화면에서 저울과 추가 잘리지 않는지 검사한다.
- 동작 줄이기에서 기울기 정보가 합계·문구로 유지되는지 확인한다.

완료 기준:

- 단위·컴포넌트·E2E·PWA 오프라인·빌드 용량 검사를 모두 통과한다.
- 브라우저 콘솔 오류와 접근성 이름 누락이 없다.

### P2 — 기존 게임과 같은 장기 동기

#### 8. 오늘의 균형 도전

- 날짜와 단계로 결정되는 재현 가능한 5문제 묶음을 만든다.
- 완료 시 하루 한 번 `오늘의 균형 배지`를 준다.
- 오늘 완료 여부를 단계 선택 화면에 표시한다.
- 홈의 오늘의 추천은 이야기만 고정하지 않고, 미완료한 오늘의 활동 중 하나를 추천할 수 있게 확장한다.

#### 9. 상위 단계 확장

- `척척`: 양쪽에 빈칸이 있고 일부 추만 사용하는 문제
- `달인`: 도형의 값을 앞 단서에서 추론하는 연속 문제
- 단계 잠금은 강제하지 않고 권장 순서만 표시한다.
- 도형은 색뿐 아니라 모양과 텍스트 대체 이름으로 구분한다.

#### 10. 성취와 도감 연결

- 속도·연속 성공 대신 학습 행동을 보상한다.
- 예시: `힌트로 배웠어요`, `추를 다시 골랐어요`, `양쪽 방향 해결`, `다른 조합 발견`.
- 별도 대형 도감을 바로 만들기보다 기존 기억력 배지 도감의 카드·진행 UI를 공통 컴포넌트로 추출한 뒤 재사용한다.

## 5. 권장 실행 순서

| 순서 | 묶음 | 예상 규모 | 선행 조건 |
|---:|---|---|---|
| 1 | 상태 reducer와 중복 입력 방어 | 중 | 없음 |
| 2 | 정확한 피드백·힌트 | 소 | 1 |
| 3 | 규칙 연습과 단계명 통일 | 중 | 1 |
| 4 | 진행·결과 UI 통일 | 소 | 1 |
| 5 | 생성 다양성과 최근 문제 회피 | 중 | 1~2 |
| 6 | 기록 v2와 전체 기록 삭제 연동 | 중 | 1 |
| 7 | 전체 세션·복구·반응형 검증 | 중 | 1~6 |
| 8 | 오늘의 도전 | 중 | 5~6 |
| 9 | 척척·달인 단계 | 대 | 3, 5 |
| 10 | 성취·공통 도감 | 대 | 6 |

P0까지 완료하면 기존 기능과 어울리는 정식 모드로 볼 수 있다. P1은 반복 플레이와 유지보수 품질을 완성하며, P2는 장기 콘텐츠 확장 범위다.

## 6. 최종 품질 게이트

- 첫 사용 아동의 80% 이상이 추가 설명 없이 규칙 연습을 완료한다.
- 모든 생성 문제는 풀이 가능하고 의도한 정답 조합이 하나다.
- 부족·초과·균형 상태에서 문구와 시각 상태가 서로 모순되지 않는다.
- 연타·드래그 중복·다음 버튼 중복으로 완료 수와 기록이 중복되지 않는다.
- 저장 중단, 새로고침, 오프라인 재방문 뒤 같은 문제에서 이어진다.
- 주요 터치 대상은 56×56px 이상이고 키보드로 동일한 조작이 가능하다.
- 상태는 색뿐 아니라 기울기·합계·문구로 전달된다.
- 320×568, 390×844, 768×1024, 1280×800과 모바일 가로 화면에서 가로 스크롤이 없다.
- 효과음 끄기, 애니메이션 끄기, 운영체제 동작 줄이기를 따른다.
- 단위 테스트, 전체 E2E, PWA 오프라인 테스트, 빌드 용량 검사를 모두 통과한다.

## 7. 이번 개선에서 제외하는 항목

- 서버 계정, 순위표, 결제, 광고
- 제한 시간과 속도 기반 보상
- 다른 아이와의 경쟁 점수
