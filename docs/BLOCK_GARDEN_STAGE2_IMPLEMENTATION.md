# 빈칸 정원 2단계 구현 기록

작성 기준일: 2026-08-30
역기획 기준: `docs/BLOCK_BLASTER_REVERSE_DESIGN.md`

## 목표와 구현 범위

이번 단계는 원작 복제가 아니라 `세 조각을 함께 살피기 → 미래의 큰 빈칸과 당장의 줄 제거 사이에서 선택하기 → 위험을 감수해 공간을 회복하기 → 기록을 넘기 위해 다시 하기`를 검증하는 첫 완성형 버전이다.

필수로 판단해 구현한 범위는 다음과 같다.

- 8×8 보드와 회전할 수 없는 17종의 독자 조각
- 세 조각을 한 묶음으로 제시하고 원하는 순서로 모두 사용한 뒤 새 묶음 지급
- 가로·세로 동시 판정과 교차 셀 중복 없는 제거
- 배치 셀 점수, 동시 여러 줄의 제곱 보너스, 여러 수 연속 제거 보너스
- 남은 조각 중 하나도 놓을 수 없을 때 게임오버
- 최고 점수·최다 제거 줄·완료 판수의 기기 저장, 진행 중인 판 자동 저장과 재개
- 탭 배치, 드래그 배치, 유효·무효 미리보기, 키보드 조작
- 게임오버 결과와 한 번의 입력으로 즉시 재시작하는 흐름
- 화면 크기와 관계없이 점수·판·조각함을 함께 확인하는 모바일/데스크톱 반응형 배치

## 독립적으로 정한 규칙

원작에서 확인하지 못한 값을 정답처럼 추정하지 않고 다음처럼 정했다.

- 점수는 `놓은 셀 수 + 40 × 이번 수에서 지운 줄 수² + 연속 제거 보너스`다. 여러 줄을 준비하는 위험에 눈에 띄는 보상을 주기 위한 값이며 이후 플레이 데이터로 조정한다.
- 콤보는 줄을 지운 수가 연속될 때 증가하고 줄을 지우지 못한 수에서 0으로 돌아간다. 사용자가 자신의 좋은 선택과 보상의 원인을 바로 연결하기 쉽다.
- 새 묶음 생성 시 현재 보드에 놓을 수 있는 조각이 최소 하나는 포함되도록 하는 약한 보정만 사용한다. 세 조각 모두를 보장하지 않아 긴장은 유지하되, 묶음을 받는 순간 아무 선택도 못 하는 억울한 종료는 막는다.
- 초반 세 묶음은 작은 조각의 비중을 낮춰 너무 단조롭게 시작하지 않게 했다. 이후에는 모양별 가중 난수를 사용한다.
- 색은 규칙 조건이 아니며 도형 안의 서로 다른 기호로도 상태를 구분한다. 원작 색상·광택 표현을 복제하지 않고 `정원을 비우고 피운다`는 밝은 시각 언어를 사용한다.
- 드래그 외에 탭과 키보드를 동등한 입력으로 제공한다. 모바일 손가락 가림에는 목표보다 위쪽을 판정하는 오프셋을 적용한다.

## 다음 단계로 미룬 범위

- 날짜별 목표나 유한 퍼즐 모드
- 배지, 성장 보상, 수집물, 온라인 순위와 계정 동기화
- 힌트, 되돌리기, 조각 교체, 광고 부활 같은 구제·수익화 기능
- 조각별 전용 사운드, 콤보 피치, 햅틱, 파티클과 고급 제거 연출
- 세밀한 난이도 곡선과 공급 보정: 실제 플레이 로그가 쌓이기 전에 복잡한 동적 난이도를 넣지 않는다.

## 검수 기준과 결과

- 규칙 단위 테스트로 배치 가능성, 행·열·교차 제거, 점수, 묶음 공급, 게임오버를 검증한다.
- 저장 단위 테스트로 정상 복원, 손상 데이터 거부, 기록 누적을 검증한다.
- 브라우저 흐름 테스트로 탭·드래그·키보드, 자동 저장 후 새로고침 재개, 줄 제거, 게임오버 기록, 즉시 재시작을 모바일과 데스크톱에서 검증한다.
- 실제 브라우저에서 모바일 한 화면 배치와 드래그를 직접 확인했다. 이 과정에서 포인터가 조각 경계를 벗어날 때 추적이 끊기던 문제와 720px 높이 데스크톱에서 조각함이 화면 아래로 밀리던 문제를 수정했다.

## 다음 단계에서 먼저 확인할 것

현재 가장 부족한 것은 장기 플레이에 근거한 공급·점수 밸런스다. 짧은 기능 검수는 완료했지만 10~20판의 실제 세션에서 평균 생존 턴, 실패 직전 점유율, 조각별 배치 실패율, 동시 제거 빈도를 수집해야 큰 조각 비중과 보너스가 의도한 선택을 만드는지 판단할 수 있다.
