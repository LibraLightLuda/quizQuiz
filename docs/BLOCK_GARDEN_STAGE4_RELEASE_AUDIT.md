# 빈칸 정원 4단계 출시 전 최종 검수

작성 기준일: 2026-08-30
검수 기준: 역기획, 2단계 구현 기록, 3단계 비주얼 기록, 현재 소스와 실제 브라우저 플레이

## 최종 결론

빈칸 정원은 **코드 기준 출시 후보(RC)** 로 볼 수 있다. 순수 규칙, 저장 검증, 화면 상태가 분리되어 있고 한 판의 시작·반복 선택·라인 제거·게임오버·기록·재시작이 닫힌 루프로 완성되어 있다. 이번 검수에서 발견한 출시 차단급 가로 휴대폰 레이아웃 문제와 피드백 상태 오류를 수정했고, 밸런스 감사 테스트의 누락 import와 완료 기록 중복 가능성도 보강했다.

다만 스토어 공개판으로 확정하기 전에는 실제 iOS Safari와 저사양 Android에서 드래그·오디오·프레임을 확인하고, 일반 사용자 10~20판으로 공급 운 편차와 한 판 길이를 확인해야 한다. 자동화가 통과했다는 이유만으로 이 실기기·사람 검수를 대체할 수는 없다.

## A. 소프트웨어 품질

### 잘된 구조

- 규칙층은 React와 저장소에 의존하지 않는 순수 함수다. 배치 가능성, 교차 제거, 점수, 공급과 게임오버를 고정 난수로 재현할 수 있다.
- 저장값은 스키마, 보드 길이, 셀·조각 종류, 음이 아닌 정수와 날짜를 검증하고 손상 데이터는 안전하게 무시한다.
- 진행 중 판과 완료 기록이 분리되어 게임오버 기록의 중복 반영 가능성을 줄였다.
- 게임 화면은 지연 로딩되고 CSS/JS가 별도 청크로 분리된다. PWA 캐시와 하위 경로 빌드도 유지된다.
- 피드백 타이머는 화면 해제 시 정리되며, 오디오 실패와 저장 실패가 플레이 자체를 중단시키지 않는다.
- 완료 기록에는 마지막 종료 판의 키를 남겨 저장 재시도나 다중 호출에서 같은 판이 `gamesPlayed`에 중복 반영되지 않도록 했다.

| 높음 | 라인 제거 직후 잘못된 위치를 누르면 실패 문구가 성공 배경색으로 표시됨 | 안내 상태를 게임의 이전 제거 셀이 아니라 `neutral/success/error`로 명시적으로 분리 |
| 높음 | 브라우저 저장소가 막혀도 자동 저장 실패를 사용자에게 알리지 않음 | 저장·기록·진행 삭제 실패 시 현재 플레이는 유지하면서 화면에 안내 |

| 높음 | 도형의 왼쪽 위 기준 배치가 손가락 중심과 어긋남 | 모든 도형의 바운딩 박스 중심 셀을 기준점으로 사용하고 중심 배치 회귀 테스트 추가 |
| 보통 | 줄 제거 성공감과 동시·연속 제거 차이가 약함 | 상승 멜로디와 제거 수·콤보에 따른 피치·점수 보너스 적용 |

### 유지보수상 남은 약점

- `BlockGardenMode.tsx`가 화면 세 개와 포인터 입력, 저장 실패 표현을 한 컴포넌트에 포함한다. 현재 크기에서는 추적 가능하지만 기능이 더 늘어나면 `useGardenGame` 상태 훅과 화면별 컴포넌트로 분리하는 편이 낫다.
- 전용 CSS는 성능에는 문제가 없지만 긴 한 줄 규칙이 많아 시각 상태를 리뷰하기 어렵다. 다음 대규모 디자인 변경 전에 포맷을 정리할 가치가 있다.
- 다중 탭에서 서로 다른 메모리를 동시에 끝내는 극단적 경쟁은 브라우저 저장소 원자성 한계가 남아 있다. 현재 동일 판의 재시도 중복은 종료 판 키로 방지하며, 계정·동기화가 없는 어린이용 로컬 앱에서의 완전한 다중 탭 조정은 출시 후 개선 범위다.

## B. 게임성 평가

### 현재 핵심 재미

핵심은 `세 조각의 순서를 고름 → 당장의 한 줄과 미래의 큰 빈칸을 교환함 → 공간 부채가 쌓임 → 준비한 제거로 점수와 생존 공간을 함께 회복함`이다. 라인 제거가 단순 점수 행동이 아니라 보드 구조를 되살리는 행동이라서 공간 관리의 원인과 보상이 일치한다.

### 질문별 판단

- **처음 무엇을 해야 하는가**: 시작 화면의 세 단계 설명, 첫 판 안내, 조각명과 탭/드래그 문구로 이해 가능하다. 별도 강제 튜토리얼 없이도 첫 수를 놓을 수 있다.
- **조작 감각**: 탭, 마우스, 손가락 드래그, 키보드가 같은 규칙으로 동작한다. 유효/무효 미리보기와 착지·점수 반응이 짧아 흐름을 막지 않는다.
- **매 턴의 선택**: 세 조각의 순서와 위치가 함께 열려 있어 중반 이후 의미가 크다. 빈 판의 첫 1~2묶음은 결과가 늦게 나타나 상대적으로 긴장이 약하다.
- **운과 실력**: 새 묶음에는 현재 놓을 수 있는 조각을 최소 하나 보장해 즉사 묶음을 막는다. 그러나 세 조각 전체의 배치 가능 순서를 보장하지 않으므로 중후반 판 길이에는 난수 영향이 남는다.
- **위기 회복과 콤보**: 한 줄 제거만으로도 8칸 공간과 큰 점수 차이가 생겨 회복감이 좋다. 연속 제거 콤보는 강하지만 빈도가 낮고, 초심자에게 만드는 방법이 명시적으로 설명되지는 않는다.
- **재도전과 판 길이**: 결과에서 점수·줄·턴을 보여 주고 한 번 눌러 재시작할 수 있다. 자동 휴리스틱 30판은 최소 26턴, 중앙 65턴, 상위 10% 125턴, 최대 206턴이었다. 짧은 실패와 오래 살아남는 판이 모두 존재하되 편차는 큰 편이다.
- **숙련감**: 최고 점수와 최다 줄로 성장 확인은 가능하다. 다만 어떤 공간 관리가 기록 향상으로 이어졌는지 사후 설명이나 중간 목표가 없어 학습은 암묵적이다.
- **독립성**: 정원 테마, 자체 점수·콤보, 접근성 입력과 광고 없는 재도전은 독립적이다. 반면 8×8, 고정 방향 세 조각, 행·열 제거라는 기계적 뼈대는 장르와 참고작에 가깝고, 차별성은 아직 규칙보다 표현에 더 많이 있다.

### 가장 잘된 부분

세 조각을 모두 본 뒤 배치 순서를 바꾸는 판단과, 라인 제거가 점수·공간 회복을 동시에 주는 연결이 가장 좋다. 거의 찬 상태에서 한 줄을 열면 보드 위험도, 빈칸 수, 점수와 애니메이션이 함께 바뀌어 플레이어가 왜 좋은 수였는지 즉시 이해한다.

### 가장 약한 부분

중장기 목표가 최고 점수 하나뿐이라 익숙해진 뒤 반복감이 빠르게 올 수 있다. 콤보는 재미있는 보상이나 의도적으로 준비하기 어렵고 설명도 약하다. 또한 동일한 휴리스틱에서도 판 길이 편차가 커, 기록이 실력보다 공급 운에 좌우되었다고 느끼는 세션이 생길 수 있다.

## 남은 문제의 우선순위

### 출시 전에 반드시 확인

1. 실제 iPhone Safari와 저사양 Android Chrome에서 손가락 드래그, 손가락 위 미리보기, 화면 회전 후 배치가 유지되는지 확인한다.
2. 소리 켜기/끄기, 첫 라인 제거 시 Web Audio 잠금 해제와 무음 실패가 플레이를 막지 않는지 확인한다.
3. 일반 사용자 10~20판에서 첫 라인까지 걸린 턴, 전체 생존 턴, 게임오버 직전 놓을 수 있던 조각 수를 기록한다. 자동 30판의 큰 길이 편차가 사람에게도 억울함으로 느껴지는지 판정한다.
4. 동작 줄이기와 색각 다양성 환경에서 유효/무효 미리보기가 애니메이션이나 색 하나에만 의존하지 않는지 실기기로 확인한다.

현재 자동 검수에서 남은 **확정 코드 차단 문제는 없다**. 단위 테스트 189개, Block Garden 브라우저 테스트 20개(모바일·데스크톱 각 흐름), 전체 브라우저 테스트 154개가 통과한다.

### 출시 후 개선 가능

- 콤보 규칙의 짧은 설명과 최고 콤보 기록
- 컴포넌트와 CSS의 유지보수용 분리·포맷 정리
- 실제 플레이 로그에 기반한 모양 가중치와 약한 공급 보정 조정

## 추가 기능을 하나만 선택한다면

**다음 묶음에서 나올 조각 하나를 `다음 새싹`으로 미리 보여 주는 기능**이 가장 효과적이다. 새 모드나 보상 경제 없이도 현재 배치가 미래에 미치는 정보를 늘려 운의 체감을 줄이고, 초반부터 빈칸을 남길 이유를 만들며, 숙련자가 더 먼 수를 계획할 수 있다. 세 조각 전체가 아니라 하나만 보여 주면 어린이 화면의 복잡도와 완전 계산 가능성을 억제하면서도 빈칸 정원만의 전략적 정체성을 강화할 수 있다.
