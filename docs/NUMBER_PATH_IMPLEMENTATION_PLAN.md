# 숫자 길 찾기 구현 계획

> 계획 원칙: 이미지 생성과 테마 일러스트는 마지막 단계로 미룬다. 먼저 숫자 길 찾기가 정확히 생성되고, 저장되고, 모바일과 키보드에서 끝까지 플레이되는 기능을 완성한다.

## 진행 계획은 세 단계만 사용한다

| 단계 | 범위 | 현재 상태 |
|---|---|---|
| 1단계: 기능 구현 | 네 난이도, 생성기, 튜토리얼, 탭·드래그·키보드, 힌트, 저장, 오늘의 길, 배지, 앱·PWA 통합 | 완료 |
| 2단계: 이미지 퀄리티업·코드 기능 점검 | 선택적 테마 이미지 제작·최적화, 화면 품질 향상, 코드 리뷰와 기능별 재점검 | 완료 |
| 3단계: 최종 전체 점검 | 기존 학습 모드를 포함한 전체 회귀 검사, 실제 화면 점검, 개선사항 검토와 반영 | 완료 |

이 문서의 나머지 항목은 별도 단계가 아니라 위 세 단계를 구현하기 위한 기술 참고 사양이다.

## 1. 목표와 완료 상태

숫자 길 찾기는 숫자판에서 서로 이웃한 칸을 이어 목표 합을 만드는 2~5분짜리 수 감각 퍼즐이다. 계산 문제를 빠르게 푸는 게임이 아니라, 다음 칸을 고르고 경로를 되돌리며 합을 계획하는 경험을 제공한다.

최종적으로 다음 상태를 만족해야 한다.

- 첫 방문자가 실제 조작 연습 뒤 긴 설명 없이 첫 문제를 시작한다.
- 모든 자동 생성 문제는 풀이 가능하고, 정답으로 인정되는 경로가 정확히 하나다.
- 탭, 드래그, 마우스, 키보드만으로 같은 문제를 완료할 수 있다.
- 틀린 경로는 실패 처리하지 않고 현재 합과 다음 생각을 알려 준다.
- 한 세션은 5문제이며 시간 제한과 힌트 감점이 없다.
- 진행 중인 경로와 문제 묶음은 새로고침 뒤 그대로 복구된다.
- 서버 없이 문제를 만들고 PWA 오프라인 상태에서도 플레이할 수 있다.
- 기능 완성 전에는 생성형 이미지를 제작하지 않는다.

## 2. MVP 규칙 계약

규칙이 구현 도중 흔들리지 않도록 MVP에서 아래 내용을 고정한다.

1. 숫자판의 한 칸에서 시작한다. 시작 칸은 문제에 표시된다.
2. 다음 칸은 현재 칸의 상·하·좌·우 중 하나여야 한다. 대각선은 허용하지 않는다.
3. 한 경로에서 같은 칸을 두 번 사용할 수 없다.
4. 문제에 적힌 `사용할 칸 수`를 정확히 채워야 한다.
5. 선택한 모든 숫자의 합이 목표 합과 같으면 완료된다.
6. 경로는 중간에 한 칸씩 되돌리거나 전체 지우기를 할 수 있다.
7. 제한 시간, 생명, 오답 감점, 연속 성공 콤보는 사용하지 않는다.

예시:

```text
목표 10 · 3칸 사용 · 별에서 시작

┌───┬───┬───┐
│ ★2│  5│  1│
├───┼───┼───┤
│  3│  5│  4│
├───┼───┼───┤
│  1│  6│  2│
└───┴───┴───┘

정답 경로: 2 → 3 → 5 = 10
```

### 정답 판정

다음 조건을 모두 만족할 때만 정답이다.

- 첫 좌표가 `startCellId`와 같다.
- 경로 길이가 `requiredLength`와 같다.
- 모든 인접 좌표의 맨해튼 거리가 1이다.
- 경로에 중복 좌표가 없다.
- 막힌 칸이 경로에 없다.
- `endCellId`가 있는 단계라면 마지막 좌표가 해당 칸이다.
- `checkpointCellIds`가 있는 단계라면 지정된 순서로 모두 지난다.
- 선택한 칸 값의 합이 `targetSum`과 같다.

MVP는 양의 정수 덧셈만 다룬다. 음수와 뺄셈 기호는 상위 단계 확장 전까지 넣지 않는다.

## 3. 학습 목표

| 행동 | 학습 의미 | 화면에서 줄 피드백 |
|---|---|---|
| 다음 칸을 고른다 | 수의 합성·분해 | `7을 만들려면 3이 더 필요해요.` |
| 남은 칸 수를 확인한다 | 계획하기 | `앞으로 2칸을 더 이어야 해요.` |
| 합을 초과해 되돌린다 | 역산·자기 수정 | `목표보다 2 커요. 마지막 칸을 되돌려 볼까요?` |
| 다른 방향을 탐색한다 | 경우의 수·공간 계획 | `이 길에서는 완성할 수 없어요. 갈림길로 돌아가 보세요.` |
| 정확한 길을 완성한다 | 등식 확인 | `2 + 3 + 5 = 10이에요.` |

정답 속도보다 스스로 수정한 행동을 긍정적으로 다룬다. 힌트를 써도 별이나 완료 기록은 줄어들지 않는다.

## 4. 단계 설계

### 기능 우선 출시 범위

| 단계 | 판 | 값 범위 | 길이 | 추가 조건 | 학습 초점 |
|---|---:|---:|---:|---|---|
| 첫걸음 | 3×3 | 1~5 | 2칸 | 고정 시작점 | 두 수의 합 |
| 쑥쑥 | 4×4 | 1~7 | 3칸 | 고정 시작점 | 세 수 계획하기 |

첫 출시에는 위 두 단계만 제공한다. 생성기와 조작 안정성을 먼저 검증하고 아래 단계는 기능 확장으로 추가한다.

### 기능 확장 범위

| 단계 | 판 | 값 범위 | 길이 | 추가 조건 | 학습 초점 |
|---|---:|---:|---:|---|---|
| 척척 | 4×4 | 1~9 | 4~5칸 | 시작점·도착점 고정, 막힌 칸 0~2개 | 목표에서 거꾸로 계획 |
| 달인 | 5×5 | -4~9 | 5~6칸 | 순서 체크포인트 1~2개, `+`·`-` 부호 칸 | 덧셈·뺄셈 혼합 |

달인의 음수 표시는 단순 `-3`으로 하며, 저학년 단계에는 노출하지 않는다. 달인 문제도 계산 결과는 매 이동 뒤 누적합으로 보여 준다.

### 단계 잠금 정책

- 강제 잠금은 사용하지 않는다.
- 단계 카드에는 `먼저 해 보면 좋아요` 정도의 권장 순서만 표시한다.
- 마지막으로 플레이한 단계를 기억한다.

## 5. 한 세션의 흐름

```text
홈
 └─ 숫자 길 찾기
     ├─ 첫 방문: 3단계 조작 연습
     └─ 단계 선택
         ├─ 일반 5문제
         ├─ 이어서 하기
         └─ 오늘의 길 찾기(기능 확장)
              ↓
          문제 화면
          길 선택 → 길 확인 → 부드러운 수정 안내 또는 완료
              ↓
          5문제 결과 → 한 번 더 / 다른 단계 / 홈
```

### 문제 화면의 정보 우선순위

1. `목표 합 10`
2. `3칸 사용`과 진행 `2 / 3칸`
3. 숫자판과 현재 경로
4. 현재 식 `2 + 3 = 5`
5. 되돌리기, 모두 지우기, 힌트, 길 확인하기
6. `문제 2 / 5`

한 화면에서 목표와 숫자판이 먼저 보이게 하고, 기록과 배지는 플레이 중 표시하지 않는다.

## 6. 조작 설계

### 탭 조작

- 시작 칸 탭: 경로 시작
- 인접한 새 칸 탭: 경로 뒤에 추가
- 직전 칸 탭: 한 칸 되돌리기
- 이미 선택했지만 직전 칸이 아닌 칸 탭: 변화 없이 이유 안내
- 멀리 떨어진 칸 탭: 변화 없이 `바로 옆 칸을 골라 주세요.` 안내

탭 조작을 기준 동작으로 먼저 구현한다. 드래그는 같은 reducer 액션을 호출하는 보조 입력으로 추가한다.

### 드래그·포인터 조작

- `pointerdown`: 시작 가능한 칸이면 `START_PATH`
- 선택하지 않은 인접 칸 위로 `pointermove`: `EXTEND_PATH`
- 직전 칸 위로 되돌아가면 `BACKTRACK`
- `pointerup`: 선택을 유지하고 자동 채점하지 않는다.
- 브라우저 스크롤과 충돌하지 않도록 숫자판 안에서만 `touch-action: none`을 적용한다.
- 포인터 좌표는 `document.elementFromPoint`로 셀을 판별한다.

자동 채점하지 않고 `길 확인하기`를 누르게 하는 이유는 손가락을 떼는 실수로 오답 피드백이 발생하지 않게 하기 위해서다.

### 키보드 조작

- 숫자판 진입 시 시작 칸에 초점을 둔다.
- 방향키: 인접 칸으로 초점 이동
- Enter/Space: 현재 칸을 경로에 추가하거나 직전 칸이면 되돌리기
- Backspace: 한 칸 되돌리기
- Escape: 경로 전체 지우기 전 확인 없이 초기화
- `길 확인하기` 버튼까지 자연스러운 Tab 순서를 유지한다.

숫자판은 `role="grid"`, 칸은 `role="gridcell"`을 사용하고, 각 칸의 접근성 이름에 행·열·숫자·선택 순서를 포함한다.

## 7. 상태 모델

권장 파일: `src/number-path/types.ts`

```ts
export type NumberPathDifficulty = 'starter' | 'growing' | 'clever' | 'master';
export type NumberPathPhase = 'selecting' | 'checking' | 'solved' | 'finished';

export interface NumberPathCell {
  id: string;          // "r1c2"
  row: number;
  column: number;
  value: number;
  blocked?: boolean;
}

export interface NumberPathPuzzle {
  id: string;
  difficulty: NumberPathDifficulty;
  rows: number;
  columns: number;
  cells: NumberPathCell[];
  startCellId: string;
  endCellId?: string;
  checkpointCellIds: string[];
  requiredLength: number;
  targetSum: number;
  solutionPath: string[];
}

export interface NumberPathProgress {
  schemaVersion: 1;
  id: string;
  difficulty: NumberPathDifficulty;
  puzzles: NumberPathPuzzle[];
  puzzleIndex: number;
  selectedPath: string[];
  completedCount: number;
  checks: number;
  backtracks: number;
  hintLevel: 0 | 1 | 2;
  phase: NumberPathPhase;
  daily: boolean;
  dateKey?: string;
  updatedAt: string;
}

export interface NumberPathDifficultyRecord {
  completedSessions: number;
  completedPuzzles: number;
}

export interface NumberPathRecords {
  schemaVersion: 1;
  lastDifficulty: NumberPathDifficulty;
  completedSessions: number;
  completedPuzzles: number;
  byDifficulty: Partial<Record<NumberPathDifficulty, NumberPathDifficultyRecord>>;
  recentSignatures: string[];
  dailyBadges: string[];
  tutorialCompleted: boolean;
}
```

`solutionPath`는 클라이언트에 저장되지만 화면에는 노출하지 않는다. 서버 경쟁 게임이 아니므로 보안 목적의 은닉은 필요하지 않고, 힌트·복구·검증의 단순성을 우선한다.

### reducer 액션

권장 파일: `src/number-path/numberPathReducer.ts`

| 액션 | 허용 상태 | 효과 |
|---|---|---|
| `LOAD` | 모든 상태 | 검증된 저장 진행 불러오기 |
| `START_PATH` | selecting | 시작 칸 하나로 경로 생성 |
| `EXTEND_PATH` | selecting | 인접·미사용·비장애물 칸 추가 |
| `BACKTRACK` | selecting | 마지막 칸 제거, 시작 칸은 유지 |
| `CLEAR_PATH` | selecting | 시작 칸만 남김 |
| `CHECK_PATH` | selecting | 정답이면 solved, 아니면 상태 유지 및 checks 증가 |
| `HINT` | selecting | 힌트 수준을 최대 2까지 증가 |
| `ADVANCE` | solved | 다음 문제 또는 finished |

모든 입력 규칙은 reducer 또는 순수 검증 함수 한 곳에서 판정한다. UI 이벤트별로 별도의 경로 규칙을 만들지 않는다.

### 반드시 지켜야 할 상태 불변식

- `selectedPath[0] === startCellId`
- `selectedPath.length <= requiredLength`
- 선택 경로에 중복 ID가 없다.
- 선택된 모든 칸은 존재하고 막히지 않았다.
- 연속된 두 칸은 상하좌우로 인접한다.
- `solved`에서는 입력으로 경로가 바뀌지 않는다.
- 한 문제의 `completedCount`는 한 번만 증가한다.
- `finished` 진행 상태는 이어하기용으로 저장하지 않는다.

## 8. 문제 생성기와 풀이 검증기

권장 파일: `src/number-path/numberPathGenerator.ts`

### 생성 방식: 정답 경로를 먼저 만든다

1. 단계에 맞는 행·열·경로 길이·값 범위를 정한다.
2. 무작위 시작 칸을 고른다.
3. DFS로 자기 자신과 겹치지 않는 정답 경로를 만든다.
4. 정답 경로에 값을 배치하고 `targetSum`을 계산한다.
5. 나머지 칸에 단계 범위의 숫자를 채운다.
6. 단계에 따라 도착점, 막힌 칸, 체크포인트를 지정한다.
7. 풀이 열거기로 가능한 정답 경로 수를 센다.
8. 정답이 정확히 하나가 아니면 나머지 값을 다시 채운다.
9. 제한 횟수 안에 실패하면 판 전체를 다시 만든다.

임의 숫자판을 만든 뒤 답을 찾는 방식은 생성 실패와 편향이 크므로 사용하지 않는다.

### 풀이 열거기

`enumerateSolutions(puzzle, limit = 2)`는 정답이 2개 발견되는 즉시 탐색을 끝낸다. 유일성 판정에는 전체 해답 목록이 필요하지 않다.

DFS 가지치기 조건:

- 이미 방문한 칸
- 판 밖 또는 막힌 칸
- 남은 이동 수로 도착점까지 갈 수 없는 맨해튼 거리
- 양수 전용 단계에서 현재 합이 목표를 초과한 경우
- 남은 칸의 가능한 최소·최대 합으로 목표에 도달할 수 없는 경우
- 남은 이동 수로 미방문 체크포인트를 모두 지날 수 없는 경우

함수 목록:

```ts
isAdjacent(first, second): boolean
pathSum(puzzle, path): number
pathEquation(puzzle, path): string
validatePath(puzzle, path): PathValidation
enumerateSolutions(puzzle, limit?): string[][]
solutionIsUnique(puzzle): boolean
viableNextCellIds(puzzle, path): string[]
numberPathPuzzleSignature(puzzle): string
generateNumberPathPuzzle(difficulty, random): NumberPathPuzzle
createNumberPathProgress(difficulty, random, options?): NumberPathProgress
```

### 문제 품질 필터

유일한 답만으로 재미가 보장되지는 않으므로 아래 문제는 버린다.

- 정답 경로가 계속 한 방향으로만 가는 단순 직선인 문제(첫걸음 제외)
- 시작 칸에서 이동 가능한 이웃 칸 자체가 1개뿐이라 생각할 여지가 없는 문제
- 오답 갈림길이 한 번도 없는 문제
- 같은 숫자 배열과 정답 좌표가 최근 10개 서명에 있는 문제
- 목표 합이 단계별 범위의 최솟값 또는 최댓값에 지나치게 붙은 문제
- 정답 경로의 숫자가 모두 같은 문제

초기 생성 재시도 한도는 문제당 200회로 두고, 테스트에서 실패율을 측정한 뒤 조정한다. 재시도 한도를 넘으면 검증된 고정 문제 묶음으로 안전하게 대체한다.

### 재현 가능한 오늘의 문제

`dateKey + difficulty + puzzleIndex`를 문자열 해시로 바꿔 `SeededRandom`에 전달한다. 같은 날짜와 단계에서는 기기와 새로고침에 관계없이 같은 5문제를 만든다.

## 9. 피드백과 힌트

### 경로 확인 결과

`validatePath`는 UI 문자열이 아니라 다음 구조를 반환한다.

```ts
type PathValidation =
  | { status: 'incomplete'; remainingCells: number; difference: number }
  | { status: 'too-low'; difference: number }
  | { status: 'too-high'; difference: number }
  | { status: 'wrong-end' }
  | { status: 'missing-checkpoint'; checkpointId: string }
  | { status: 'dead-end' }
  | { status: 'solved'; equation: string };
```

문구 예시:

- 칸 부족: `2칸을 더 이어야 해요. 목표까지 4가 더 필요해요.`
- 합 부족: `3칸을 골랐지만 목표보다 2 작아요. 마지막 숫자를 바꿔 볼까요?`
- 합 초과: `목표보다 3 커요. 한 칸 되돌려 다른 길을 찾아보세요.`
- 막힌 경로: `이 길에서는 목표를 만들 수 없어요. 갈림길까지 되돌아가 보세요.`
- 완료: `2 + 3 + 5 = 10! 목표 합과 같아요.`

### 힌트 단계

- 1차: 현재 합, 남은 칸 수, 목표와의 차이만 말한다.
- 2차: `viableNextCellIds`가 반환한 다음 후보 칸에 점 표시를 한다. 현재 경로로 완성할 수 없다면 되돌려야 할 마지막 칸을 표시한다.
- 풀이 보기: 결과나 별과 무관한 별도 확인 동작으로 전체 경로를 순서대로 보여 준다. 첫 기능 출시에서는 제외하고 품질 향상 단계에서 추가한다.

힌트는 정답 경로 배열을 바로 비교하는 대신 현재 경로에서 실제로 완성 가능한 후보를 solver로 계산해야 한다. 그래야 정답 경로와 같은 칸을 우연히 다른 순서로 고른 경우에도 정확한 안내가 가능하다.

## 13. 2단계 이미지 퀄리티업·코드 기능 점검 참고 사양

### Q1 — 코드 기반 시각 품질

- 선택 경로를 굵고 둥근 SVG 선으로 연결한다.
- 시작점, 도착점, 체크포인트를 모양과 텍스트로 구분한다.
- 올바른 경로 완성 시 선이 한 번만 부드럽게 빛난다.
- 경로를 되돌릴 때 선이 즉시 짧아져 조작 결과가 분명하게 보인다.
- 밝은 화면과 높은 대비에서 숫자·선·배경 대비를 확인한다.
- 홈 아이콘은 작은 숫자 격자와 경로를 표현하는 SVG로 만든다.

완료 기준:

- 이미지 로딩 없이 모든 핵심 정보가 보인다.
- 색각 차이가 있어도 선택 순서와 시작·도착을 구분한다.
- `prefers-reduced-motion`에서는 경로와 완료 애니메이션을 제거한다.

### Q2 — 소리·촉각·미세 연출

- 칸 추가, 되돌리기, 완료에 서로 다른 짧은 효과음을 사용한다.
- 설정에서 효과음을 끄면 즉시 정지한다.
- 지원되는 모바일에서만 완료 시 짧은 진동을 선택적으로 사용한다.
- 잘못된 칸에는 경고음을 내지 않고 문구와 가벼운 흔들림만 사용한다.

효과음은 기존 앱의 설정·오디오 정책을 재사용하고 새 전역 설정을 만들지 않는다.

### Q3 — 사용자 관찰을 통한 난이도 조정

대상:

- 초등 1~2학년 3명 이상
- 초등 3~4학년 3명 이상

관찰 항목:

- 말로 추가 설명하지 않아도 시작 칸을 누르는가?
- 대각선이 안 되는 이유를 이해하는가?
- 길을 되돌리는 방법을 발견하는가?
- 합이 초과했을 때 무작정 새 칸을 더 누르지 않는가?
- 5문제 뒤 다시 하기를 스스로 선택하는가?

성공 기준:

- 80% 이상이 첫 연습 뒤 조작 설명 없이 첫 문제를 시작한다.
- 80% 이상이 세 번째 문제 전까지 혼자 되돌리기를 사용한다.
- 한 세션에서 조작 방식 때문에 중단하는 아이가 없다.
- 첫걸음 한 문제의 중앙 완료 시간이 60초 이하다. 시간은 평가에 노출하지 않는다.

관찰 결과에 따라 숫자 범위, 갈림길 수, 목표 문구를 조정하되 핵심 규칙은 바꾸지 않는다.

### Q4 — 이미지 생성과 테마 확장(최후순위)

기능·접근성·난이도 검증 뒤에만 진행한다.

가능한 테마:

- 숲속 보물 지도
- 우주 별자리 항로
- 바닷속 진주 길

이미지 사용 범위:

- 단계 선택 카드의 배경 장식
- 결과 화면의 작은 축하 스티커
- 빈 공간의 비상호작용 장식

이미지로 만들지 않을 것:

- 숫자 칸
- 선택 경로
- 시작·도착·체크포인트 상태
- 힌트와 정답 표시
- 홈에서 의미를 전달하는 유일한 아이콘

핵심 상태를 이미지에 넣지 않아야 오프라인, 고대비, 작은 화면, 다국어 접근성을 유지할 수 있다. 생성 이미지에는 글자와 숫자를 포함하지 않고, WebP 변환과 크기 최적화 후 PWA 캐시 예산을 다시 측정한다.

## 15. 접근성·반응형 완료 기준

- 모든 상호작용 칸과 버튼은 최소 48×48px, 주요 버튼은 56px 이상이다.
- 320×568, 768×1024, 1280×720에서 핵심 조작이 잘리지 않는다.
- 5×5 달인 판도 320px에서 숫자가 최소 18px로 보인다.
- 현재 합과 경로 길이는 `aria-live="polite"`로 알린다.
- 완료 알림은 한 번만 읽힌다.
- 경로선만으로 선택을 표현하지 않고 각 칸에 선택 순서 숫자를 표시한다.
- 시작·도착·장애물은 색과 함께 모양·문구를 사용한다.
- 키보드 초점 표시가 경로선 아래에 가려지지 않는다.
- 확대 200%에서도 숫자판과 확인 버튼을 사용할 수 있다.

## 16. 성능·오프라인 기준

- 초기 앱 번들에 게임 코드를 넣지 않고 lazy chunk로 분리한다.
- 숫자 길 찾기 JavaScript gzip 청크는 30KB 이하를 목표로 한다.
- 첫 화면은 생성기 작업 때문에 100ms 이상 멈추지 않는다.
- 5문제 생성이 길어지면 문제별로 이벤트 루프에 양보하거나 미리 생성한다.
- 기능 단계에는 외부 네트워크 요청이 없다.
- 이미지 단계 전에는 추가 PWA 정적 자산이 없다.
- 이미지 추가 후에도 기존 초기 번들 예산과 lazy chunk 예산을 통과한다.

## 19. 출시 판단 체크리스트

### 작업량과 의존 관계

일정 대신 상대 작업량을 사용한다. `1점`은 순수 함수와 테스트 한 묶음, `3점`은 독립 화면 한 흐름, `5점`은 여러 입력·저장·통합이 함께 필요한 작업을 뜻한다.

| 티켓 | 선행 작업 | 결과물 | 상대 작업량 |
|---|---|---|---:|
| 1. 타입·solver·생성기 | 없음 | 검증된 첫걸음·쑥쑥 문제 | 5 |
| 2. reducer·탭 숫자판 | 1 | 탭으로 한 문제 완료 | 5 |
| 3. 세션 화면·홈 진입 | 2 | 5문제와 결과 화면 | 3 |
| 4. 튜토리얼·드래그·키보드 | 2 | 세 입력 방식 완성 | 5 |
| 5. 힌트·저장·기록 | 1~4 | 새로고침 복구와 기록 | 5 |
| 6. 전체 자동 검증 | 1~5 | 릴리스 게이트 증거 | 5 |
| 7. 척척·달인 | 6 | 고급 제약과 음수 | 5 |
| 8. 일일 도전·성취 | 5~7 | 장기 동기 기능 | 3 |
| 9. 코드 기반 품질 향상 | 6 | 시각·소리·동작 개선 | 3 |
| 10. 선택적 이미지 테마 | 9 및 사용자 관찰 | 최적화된 장식 자산 | 3 |

기능 출시의 임계 경로는 `1 → 2 → 3·4 → 5 → 6`이다. 3과 4는 reducer 계약이 고정된 뒤 병행할 수 있다. 7~10은 기능 출시의 필수 조건이 아니다.
